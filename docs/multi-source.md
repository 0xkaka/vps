# 多来源整合

2026-10-20 接入以下公开页面：

- https://stock.vpszdm.com/
- https://stock.bwh91.com/
- https://stock.dmitea.com/
- https://matrix.bwh91.com/
- https://matrix.dmitea.com/

两个大全共识别 160 个不同的型号/机房/购买地址组合（各页包含镜像数据）；独立库存页分别有 23、32 条。跳过一个空的“正价套餐”标题。保留同名不同 PID 和共用购买链接但配置不同的型号，不单独以购买链接去重。与原有数据匹配后，补充 146 条、完善 26 条，最终 278 条含 17 个分组，机房明细仍为 172 条。

明确匹配到独立库存页的产品使用该页库存。其他新型号使用产品大全的状态；大全没有原站检查时间，页面显示“来源未提供检查时间”，另外显示本站同步时间。需邀请码不等于可以直接购买；说明保留限制，大全中的此类状态记为 UNKNOWN。参考价格保存在说明中，不承诺实时结算价。

后台产品编辑可选择库存来源页面和匹配键。只允许固定白名单，拒绝任意抓取地址和重定向；每个来源请求超时 15 秒，单来源失败记录日志并保留原库存，不阻断其他来源。每轮完成后间隔 120 秒运行，各产品间隔默认为 120 秒；抓取和页面刷新会带来额外延迟。同步只更新状态和检查时间，新增型号/资料变更需要再导入或后台维护，不会自动覆盖运营文案。

首页的两个大全及两个补货入口切换到本页相应商家分组。每条产品保留来源链接，测速、透镜、测评、教程继续使用外链。

## 已有部署升级

先备份。仅执行一次 `sql/mysql/migrations/20261020_multi_source.sql`，再执行一次 `sql/mysql/vps-extended-seed.sql`。扩展种子针对初始 132 条记录制作，含固定 ID；不可在已增改产品的数据库盲目重复导入。首次部署的 bootstrap.sh 已包含扩展数据，无需重复执行迁移。

`tools/build_extended_catalog.py` 从保存的四个 HTML 页面和现有 catalog JSON 生成可审查 SQL，需要 beautifulsoup4；不会读取凭据或直接修改数据库。再次扩展应重新获取当前目录并人工审查合并结果，不能直接复用旧种子。
